# cc-backfill-lab

CC_Codex 二期（26.11）**数据工程**产品线：**回灌补数台**（Falcon ASGI + 原生 JS SPA + SQLite）。

## 一句话骨架（自有，非外仓抄题）

**回灌窗口 → 按日切片计划 → 重放落库 → 覆盖对账**

与现有线正交（不是契约换版、水印、清单、留存、采集/ETL/同步/解析/编排/摄取）。
不碰外仓常见指纹（Feed 归并 / CDC 游标 / 质检签发 / Slicegate 类仓名）。

## 领域

- **所属领域**：数据工程
- **子方向**：数仓与数据湖（历史回灌 / 补数闭环）

## 技术栈

| 层 | 选型 |
|----|------|
| 后端 | Python 3.12、Falcon ASGI、Uvicorn、SQLite |
| 前端 | 原生 JS SPA（全中文），靛青底 + 蜜橙强调；卡片墙，无侧栏/底栏 |
| 测试 | pytest + httpx ASGI（本地秒级闭环） |

## 基线已通主链

1. 登记回灌窗口（目标表 / 起止日）
2. 生成按日切片计划
3. 单片重放落库
4. 计划覆盖对账

预留切口（未做）：整窗失败闭 vs 单片独立事务、与在线灌数互斥、重叠窗拒入、切片并发锁等。

## 防重纠偏重放（已收口）

同片连点只许二选一落库，本项目选的是 **先到的行留在目标表，后到的行进只读历史并拒再点**：

- `replay_hits.slice_key` 上有唯一索引 `ux_replay_hits_slice_key`，防重写库不再靠注释；
- 放行门槛与片键唯一 **同源**（都看这个索引 + 片键现行/门槛一致），双键不一致即整体拦下、不落库；
- 重放走 `BEGIN IMMEDIATE`，两名值班并发只写一行；
- 主链同一片二次重放直接 409（“该片已落库，拒再点”），覆盖计划条数不翻倍；
- 页面四处核对：防重队列（防重芯片）、片键详情（同源）、放行卡片（放行号 P0001）、覆盖附页（条数只认一次成功）。

复现纸见 [`docs/repro-backfill-bug-04.md`](docs/repro-backfill-bug-04.md)。
